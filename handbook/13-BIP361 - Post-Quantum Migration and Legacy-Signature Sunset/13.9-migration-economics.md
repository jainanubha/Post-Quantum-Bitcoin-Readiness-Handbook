# 13.9 Migration economics and block-space constraints

## Separate migration cost from future PQ spending cost

Chapter 11 develops transaction accounting for hypothetical PQ authorization. A migration before a legacy sunset normally spends the old output using its existing witness or scriptSig. The size of the new PQ signature is charged when that new output is spent, unless the migration itself includes such authorization. Rescue rules could change the old-input cost; no final rescue encoding is available to price.

For stripped size $B$, additional witness bytes $D$, fee rate $r$ and weight $W$,

$$W=4B+D,\qquad v=\lceil W/4\rceil,\qquad F=\lceil rv\rceil.$$

## Worked example: one-to-one migration

Assume an existing P2TR key-path input with a 64-byte signature, one new 34-byte output script, empty scriptSig, no annex and counts below 253. Stripped size is $10+41+43=94$ bytes. Marker/flag contribute two bytes, and the witness contributes $1+1+64=66$ bytes. Thus $D=68$, $W=444$ WU and $v=111$ vB. The destination is hypothetical; these sizes do not authorize use of an unactivated output type.

| Fee rate (sat/vB) | Fee per migration (sat) | Aggregate fee for 1 million identical migrations (BTC) |
| ---: | ---: | ---: |
| 1 | 111 | 1.11 |
| 5 | 555 | 5.55 |
| 10 | 1,110 | 11.10 |
| 50 | 5,550 | 55.50 |

One million such migrations consume 444 million WU. Fees are paid to miners.

## Capacity and deadlines

For available ordinary-transaction weight $L=3,960,000$ WU per block (an illustrative reserve below the 4 million WU limit), share $a$ available for migration, and identical migration weight $w$, define

$$K=\left\lfloor\frac{a L}{w}\right\rfloor,\qquad N_{blocks}=\left\lceil\frac{N}{K}\right\rceil.$$

Assume $K>0$ and complete transactions, no other binding resource constraint, no failures, and a mean ten-minute block interval. For $N=1,000,000$, the model gives:

| Share | Transactions per block | Blocks | Expected time (days) |
| ---: | ---: | ---: | ---: |
| 100% | 8,918 | 113 | 0.78 |
| 50% | 4,459 | 225 | 1.56 |
| 10% | 891 | 1,123 | 7.80 |
| 5% | 445 | 2,248 | 15.61 |
| 1% | 89 | 11,236 | 78.03 |

This is a homogeneous packing scenario, not a reservation of network capacity. Across the proposed 160,000-block interval, a constant 1% share in this model could accommodate 14.24 million migrations. That is not a claim about the actual number of affected UTXOs. Mixed script types, available signers, output design, fee competition and user delay all alter the result.

## Consolidation and economic exclusion

Combining ten existing P2TR inputs into one hypothetical compact output gives $B=463$, $D=662$, $W=2514$, $v=629$. At 10 sat/vB it costs 6,290 sat instead of 11,100 sat for ten independent one-to-one moves. It still requires ten old signatures. Consolidation changes denominations and can link inputs, so it is not appropriate for unrelated owners without cooperation or for all privacy-sensitive wallets.

For output value $x$, a simple one-output migration leaves $x-F$ sat. If the fee exceeds the value, that individual migration is economically infeasible. Even a positive remainder may be too small to spend later or may violate relay policy. Economic infeasibility is not the same as a lost key. A deadline can disproportionately burden smaller holdings, particularly if fee demand increases.
