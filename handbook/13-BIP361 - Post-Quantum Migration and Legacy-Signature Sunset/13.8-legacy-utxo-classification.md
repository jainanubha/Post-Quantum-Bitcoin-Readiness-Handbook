# 13.8 Dormant, lost and unmigrated coins

## Classification is multidimensional

An output's script type determines some public information but does not establish its wallet history, owner availability or recoverability. The same P2WPKH output can be controlled by an HD seed, a standalone imported key or a custody arrangement. On-chain inactivity cannot distinguish a long-term holder from a lost key. We propose an educational record with separate dimensions:

| Dimension | Possible values |
| --- | --- |
| Script family | P2PK, P2PKH, P2WPKH, P2SH, P2WSH, P2TR, other |
| Public-key exposure | Directly visible; historically revealed; hidden on-chain; unknown off-chain |
| Authorization path | Single key; threshold policy; script-dependent; unknown |
| Owner accessibility | Available; inaccessible; unknown |
| Recovery evidence | Potential HD proof; hidden key/script; prior commitment; none known; unknown |
| Economic feasibility | Spendable at modeled fee; uneconomical at modeled fee; unknown |

The latter dimensions often cannot be determined from blockchain data alone. The matrix therefore labels possibilities rather than assigning confirmed recovery eligibility.

## Representative legacy classes

| Class | On-chain exposure | Potential recovery research |
| --- | --- | --- |
| P2PK or bare multisig | Public keys appear directly | Independent provenance secret if one exists; no universal method |
| Fresh P2PKH / P2WPKH | Key hash visible; key normally hidden | Hidden-key commitment or suitable HD proof |
| Reused key-hash output | Relevant key may already be public | Independent evidence beyond the scalar or public key |
| P2SH / P2WSH | Script commitment visible | Depends on disclosure and authorization inside the script |
| P2TR | Output key visible | HD derivation and tweak proof for applicable wallets; other cases differ |

BIP361 highlights early P2PK outputs as especially difficult because a suitable independent recovery secret is not known in general. Many historical outputs predate BIP32. A newer output of the same type might nevertheless have independent wallet secrets. Script family is not a sufficient proof of provenance.

## Dormancy and ownership

A dormant output may remain deliberately untouched for years. A lost output has no accessible authorization material under the relevant rules. An unmigrated output simply has not been moved into a new protected spending condition. The three categories overlap but are not equivalent. Classifying all dormant outputs as lost would overstate the evidence available to policymakers and could misrepresent the impact of a sunset.

A proposed rescue predicate should preserve legitimate access wherever possible, but recovery eligibility cannot be inferred solely from output age or denomination. A hardware wallet owner might know the seed yet lack script metadata; an institutional holder may have distributed shares; a beneficiary may possess only a presigned transaction. These cases require different analyses.

## Example assessment

Two outputs have equal value and the same P2TR script form. One was generated from an available BIP86-compatible HD wallet; the second uses an imported private scalar with no independent secret retained. Both expose an output key. The first may admit a future proof of HD derivation, subject to actual rules and disclosure history. The second cannot be assumed to do so. Neither is currently subject to a BIP361 rescue rule.
