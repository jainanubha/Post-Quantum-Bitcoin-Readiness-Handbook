# 13.1 Introduction and motivation

## Learning objectives

- Explain why an opt-in post-quantum output type does not automatically protect the existing UTXO set.
- Distinguish adoption, migration, retirement of old authorization mechanisms and recovery.
- Interpret the two phases of BIP361 without confusing a proposal with active consensus rules.
- Evaluate trade-offs between theft prevention, legitimate access and decentralized coordination.

## From cryptographic primitives to migration

Bitcoin's ownership model is expressed through spending conditions on unspent transaction outputs (UTXOs), not through a central account database. A newly introduced signature algorithm does not alter the conditions of an old output. A holder must ordinarily spend that output under its existing conditions and create a new output protected by the new mechanism. An upgrade can also restrict what constitutes a valid spend, but doing so raises a different set of technical and governance questions.

Chapter 12 examined BIP360, which removes the exposed elliptic-curve output key from a proposed script-tree output. This is an output-level response to persistent public-key exposure. It neither defines a new PQ signature algorithm nor changes old UTXOs. Chapter 13 considers the transition problem left open by such a construction: how can a network with many independently controlled outputs retire a vulnerable form of authorization?

BIP361 proposes an announced migration schedule followed by tighter legacy authorization rules. Its authors intend to reduce the amount of value susceptible to quantum key recovery and encourage users to update before that capability becomes practical. These are design objectives, not demonstrated outcomes. The schedule creates a cost for postponing migration, while an incomplete rescue mechanism could also create a cost for legitimate users who cannot move in time.

## Scope and source policy

The specification basis is the canonical `bitcoin/bips` text at commit `da7cc678d522c7ff09d3d4e3b5de1a1ccc1e90c9` (April 17, 2026; retrieved November 28, 2026). BIP361 is informational and remains a draft. Its prerequisite signature BIP is unspecified. Other discussions are identified separately, including earlier versions that proposed a distinct recovery phase. The chapter treats quantum hardware capability as uncertain, and the economic examples as synthetic.

## Key distinctions

| Concept | Meaning in this chapter |
| --- | --- |
| PQ adoption | Availability and use of a new authorization mechanism |
| Migration | Moving an existing UTXO into a new spending condition |
| Sunset | Restricting previously permitted legacy authorization |
| Rescue | A proposed additional condition allowing legitimate legacy spending under stronger assumptions |
| Activation | Enforcement of new consensus rules by upgraded nodes |

A useful organizing question is not simply whether a signature withstands a quantum attack, but whether a migration policy can preserve security and legitimate access for a heterogeneous set of users.
