# 12.12 Limitations and open research problems

## Summary

P2MR is a proposed script-tree output designed to avoid Taproot's persistent elliptic-curve output-key exposure. It retains Merkle proof-based script revelation and Tapscript extensibility, removes the internal key and direct key path, and uses a 32-byte root commitment in a version-2 witness program. The reviewed draft does not specify a post-quantum signature verifier. Its protection depends on the security and disclosure of the committed leaves, the validation rules, and the assumptions of the threat model.

## Research agenda

| Area | Open question | Evidence needed |
|---|---|---|
| Commitment security | How do multi-target and low-entropy policy attacks affect script-tree commitments? | Formal threat model and concrete estimates |
| Depth-zero semantics | What are the safety and upgradeability implications for wallet policy construction? | Consensus review and wallet policy analysis |
| Script privacy | What does path depth reveal about common policy shapes? | Representative policy models and leakage analysis |
| Quantum exposure | Which wallet practices disclose hidden leaf keys before spend? | Key lifecycle and data-disclosure inventory |
| Future signature support | Which consensus extension can support PQ encodings safely? | Concrete proposals, test vectors and resource analysis |
| Performance | How much work does removing tweak reconstruction save relative to actual signature verification? | Reproducible measurements on representative nodes |
| Economics | How do script depths and future PQ witnesses change fee demand? | Transaction models and workload scenarios |
| Multiparty authorization | Can future PQ threshold schemes preserve cooperative spending efficiency? | Security proofs, communication and size measurements |
| Migration | How should users migrate if legacy keys are already vulnerable? | Threat models, recovery proposals and economic analysis |
| Deployment | What review, activation and interoperability work is needed? | Community review and implementation evidence |

The performance row is deliberately unquantified: removing elliptic-curve tweak reconstruction changes validation work, but does not establish a measured speedup across a full workload. Similarly the size analysis in Section 12.9 is exact only for its explicit templates, not a network forecast.

## Conclusion

The proposal highlights the difference between reducing public-key exposure and completing a cryptographic migration. Even if an appropriate output construction and PQ authorization mechanism become available, the existing UTXO set remains governed by its established spending conditions until users migrate or new rules affect those conditions. The economic, operational and governance problems surrounding that transition are the subject of BIP361 and Chapter 13.
