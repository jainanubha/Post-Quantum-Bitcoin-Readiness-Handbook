# 12.8 Comparison with P2TR and P2WSH

## Three output constructions

P2WSH commits to the SHA-256 hash of a complete witness script and uses SegWit version 0. P2TR uses SegWit version 1 and commits to a tweaked x-only public key. Draft P2MR uses version 2 and commits directly to a script-tree root. All three can use a 32-byte witness program, yet the interpretation of those bytes differs fundamentally.

| Feature | P2WSH | P2TR | P2MR (draft) |
|---|---|---|---|
| Commitment | SHA-256 of witness script | Tweaked output key | Script-tree Merkle root |
| Native key path | No | Yes | No |
| Merkle script proofs | Not native | Yes | Yes |
| Script language | SegWit v0 Script | Tapscript for version `0xc0` | Proposed Tapscript reuse |
| Output-level curve key | None | Present | None |
| Unused scripts hidden on spend | Full witness script revealed | Yes, unless separately disclosed | Yes, unless separately disclosed |
| Ordinary signature authorization | ECDSA | Schnorr | Schnorr in current Tapscript leaves |
| Active consensus support | Yes | Yes | No |

The comparison is expanded in the [supporting reference table](../../tables/p2tr-p2wsh-p2mr-comparison.md).

## Privacy trade-offs

P2WSH reveals the complete witness script when spent, even if only one conditional branch is used. A script-tree spend in P2TR or P2MR reveals the chosen leaf plus the hash path rather than all the leaf scripts. The control block reveals path depth, but sibling hashes can represent subtrees or disabled alternatives. They do not reveal a reliable count of usable spending policies. Hash guesses, key reuse and external disclosure can also reduce privacy.

P2TR key-path spending can conceal whether additional script policies even exist. P2MR always requires a script proof under the proposed rules, so its ordinary enforced spends disclose the executed policy and path depth. This is a meaningful loss of privacy for wallets currently relying on cooperative key-path spending. The output type itself is also distinguishable by its witness version.

## Functionality and migration

P2WSH already provides a hash-committed output without an exposed elliptic-curve program, but it lacks the Tapscript upgrade mechanisms and native script-tree proof format. P2MR's rationale is to combine script-tree functionality with the absence of an exposed direct output key. It is not a claim that P2WSH has no quantum-related risks or that users must migrate to P2MR.

Consider a cooperative two-party wallet that uses an aggregated Schnorr key in P2TR and a recovery leaf. The ordinary key-path spend can be compact and indistinguishable from a single-key spend. A P2MR redesign might put a cooperative aggregated key in an enforced leaf and a timelocked condition in a second leaf. This retains a form of cooperative authorization but reveals the chosen script when used. It also leaves the cooperative key's quantum vulnerability intact once exposed. A future PQ threshold construction would require separate research.

## Design trade-off

The appropriate comparison depends on the use case: script complexity, desired privacy, exposure of keys, frequency of spends, future signature needs and wallet interoperability.
