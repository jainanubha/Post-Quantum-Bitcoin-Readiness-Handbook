# 9.8 Mathematical foundations of hash-based signatures

Hash-based signatures construct public verification from hash-function properties rather than elliptic-curve or lattice problems. The security of a complete scheme depends on how its hash functions, pseudorandom functions and signing procedures are composed. A hash alone is not a digital signature.

## One-time signatures

Lamport's construction illustrates the basic idea. For each bit position of a fixed-length message digest, the signer generates two random secret strings and publishes their hashes. To sign, the signer reveals the secret corresponding to the value of each digest bit. The verifier checks each disclosed value against the committed hash. This construction is one-time: signing different digests with the same key can disclose additional secrets and enable forgery. A one-time key should therefore not be treated like an ordinary reusable signing key. The construction is also large, because each digest bit requires separate secret and public material.

## Winternitz signatures and Merkle authentication

Winternitz constructions encode message digits using hash chains to reduce signature size. A checksum limits an adversary's ability to transform a signature by advancing the chains. WOTS+ refines this approach using keyed, address-dependent hash operations. A Merkle tree commits to a collection of one-time public keys in a single root. A signature can include an authentication path enabling a verifier to reconstruct that root from a leaf. This separates the compact long-term public commitment from the larger proof needed for an individual signature.

XMSS and LMS are examples of stateful hash-based signature schemes. Their signing state must ensure that one-time keys are not reused. Rollback, concurrent signing and restoration of an old backup can violate this requirement. NIST SP 800-208 specifies stateful constructions under particular usage requirements.

## Stateless hash-based signatures

SLH-DSA uses a hypertree of smaller Merkle trees and a few-time signature component called FORS (Forest of Random Subsets). Its message-derived selection and security analysis allow signing without an externally maintained monotonic leaf counter. Stateless does not mean unlimited use: security depends on the permitted number of signing queries and on the parameter set.

## Bitcoin context

Bitcoin already uses Merkle commitments, but an existing Taproot script tree is not itself a hash-based digital signature scheme. An authentication path demonstrates membership; a complete spending rule must additionally ensure that only the authorized party can satisfy the committed condition. Limited-use signatures are interesting in a UTXO setting, yet signing several alternative transactions for the same output can violate one-time restrictions even when only one transaction confirms.
