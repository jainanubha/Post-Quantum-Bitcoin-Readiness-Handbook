# 11.5 Classical transaction-size baselines

The classical baselines must be explicit about their spending paths and output types. Here every transaction has one input and two 34-byte output scripts (43 bytes each), so the recipient and change output lengths are held fixed. This isolates differences between input authorization formats. All signatures are assumed valid for their respective paths.

## P2PKH input

Assume a compressed 33-byte public key and a 72-byte ECDSA transaction signature, including its one-byte sighash type. The signature is an assumed length, not a fixed DER encoding requirement. For these lengths, both pushes use one-byte push opcodes. The scriptSig is $1+72+1+33=107$ bytes. Its outer CompactSize length uses one byte. The input occupies $40+1+107=148$ stripped bytes. With two 43-byte outputs and ten bytes of transaction-level overhead, $B=244$ B. This is a non-witness transaction with $D=0$, $W=976$ WU and $v=244$ vB.

## Native P2WPKH input

The scriptSig is empty, so the stripped input is 41 bytes. The 72-byte transaction signature and 33-byte compressed public key are witness items. The vector length is $1+(1+72)+(1+33)=108$ B. With marker and flag, $D=110$ B. The stripped size is $10+41+86=137$ B, so $W=658$ WU and $v=165$ vB.

## P2TR key-path input

The stripped input is also 41 bytes. A default-sighash BIP340 signature is 64 bytes with no appended sighash byte; a non-default valid sighash encoding uses 65 bytes. With a 64-byte signature, the witness vector occupies $1+1+64=66$ B. Including marker and flag gives $D=68$ B. With $B=137$ B, the weight is 616 WU and the virtual size is 154 vB. No public key is provided in this key-path witness: the previous output already contains the tweaked output key.

## Baseline comparison

| Input type | Stripped (B) | Witness delta (B) | Total (B) | Weight (WU) | vsize (vB) | Fee at 10 sat/vB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P2PKH | 244 | 0 | 244 | 976 | 244 | 2,440 sat |
| P2WPKH | 137 | 110 | 247 | 658 | 165 | 1,650 sat |
| P2TR key path | 137 | 68 | 205 | 616 | 154 | 1,540 sat |

A familiar alternative baseline is one P2WPKH input and two P2WPKH outputs. The outputs now each occupy 31 bytes, giving $B=113$ B, $W=562$ WU and $v=141$ vB.

## Script-path baseline

For a simple Taproot script path with one 32-byte key followed by `OP_CHECKSIG`, a signature-only initial stack, a 34-byte tapscript and a 33-byte control block at Merkle depth zero, the witness vector is $1+65+35+34=135$ B. With marker and flag, $D=137$ B, and the same 137-byte stripped transaction gives $W=685$ WU and $v=172$ vB. This example has no annex, default sighash and no additional stack items. At depth $h$, the control block grows by $32h$ bytes plus any length-prefix increase. The script path overhead should not be treated as a fixed overhead for every design.
