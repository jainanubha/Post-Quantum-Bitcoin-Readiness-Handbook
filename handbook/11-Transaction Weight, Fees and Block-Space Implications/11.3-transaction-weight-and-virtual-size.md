# 11.3 Transaction weight and virtual size

Segregated Witness introduced weight-based accounting. The consensus block limit is 4,000,000 weight units; it is not a fixed four-megabyte allowance for every combination of transaction data. A byte in the stripped serialization contributes four weight units, while an additional witness serialization byte contributes one.

## Definitions

Let $B$ be stripped size and $T$ be total serialized size. BIP141 defines transaction weight as

$$
W=3B+T=4B+(T-B)=4B+D.
$$

The virtual size is

$$
v=\left\lceil W/4\right\rceil.
$$

A non-witness transaction has $T=B$ and therefore $v=B$. A witness transaction can have a substantially greater total byte size than virtual size. Network transmission and archival storage still involve serialized bytes; weight is not a compression algorithm.

## Worked examples

Consider a transaction with 137 stripped bytes and 68 additional witness bytes. Its total serialization is 205 bytes, weight is $4(137)+68=616$ WU and virtual size is 154 vB. A hypothetical transaction with the same stripped fields and 3,741 additional witness bytes weighs 4,289 WU and occupies 1,073 vB. The rounding is applied only after summing the full transaction weight.

| Modification | Change in raw bytes | Change in weight |
| --- | ---: | ---: |
| Add 100 stripped bytes | 100 | 400 WU |
| Add 100 witness bytes | 100 | 100 WU |
| Move 100 bytes from stripped to witness serialization, if a valid design permits | 0 | −300 WU |

The last row assumes no additional framing or changes to other fields. It is an accounting identity, not a mechanism for moving arbitrary data into the witness under current consensus.

## Distinguish weight, vsize and policy accounting

BIP141 vsize is the size-based metric used here. Bitcoin Core also has policy accounting that can increase effective virtual size for certain transactions with high signature-operation costs. A future PQ mechanism may require different accounting entirely. A weight calculation alone does not prove consensus validity, policy acceptance or an adequate validation-resource bound.

Block weight is the weight of the complete block serialization, including header, transaction count, coinbase and witness data. Consequently the sum of ordinary transaction weights must fit into a budget smaller than the total limit. Summing each transaction's rounded vsize is not exactly the same as rounding total weight divided by four.
