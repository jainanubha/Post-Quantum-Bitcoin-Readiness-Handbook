# 11.4 Transaction fees and fee rates

Bitcoin transaction fees are not an explicit serialized field. For a valid non-coinbase transaction, the fee is the difference between the total value of the UTXOs consumed and the total value of the outputs created.

$$
F=\sum_i V_i^{\mathrm{in}}-\sum_j V_j^{\mathrm{out}}.
$$

Fees are nonnegative and expressed in satoshis. Given virtual size $v$, the realized fee rate is $F/v$ sat/vB. A wallet targeting rate $r$ can budget $F_r=\lceil rv\rceil$ satoshis. This is a modelling convention for meeting or exceeding the target; a wallet's actual rounding, coin selection and policy decisions may differ.

## Fee calculation example

For a 154-vB transaction at 10 sat/vB, the target fee is 1,540 sat. If the total input value is 100,000 sat and the recipient is assigned 60,000 sat, a change output of 38,460 sat produces the intended fee, provided this is the complete two-output transaction model. If change is omitted, the size and fee must be recomputed; the residual value becomes the fee. A hypothetical 1,073-vB PQ transaction with the same input and payment would require 10,730 sat at the same fee rate. Its change would be 29,270 sat. Larger authorization data therefore affects not only fee expenditure, but also coin selection and the feasibility of maintaining a viable change output.

## Fee-rate scenarios

| Virtual size | 1 sat/vB | 5 sat/vB | 10 sat/vB | 50 sat/vB |
| ---: | ---: | ---: | ---: | ---: |
| 154 vB | 154 | 770 | 1,540 | 7,700 |
| 1,073 vB | 1,073 | 5,365 | 10,730 | 53,650 |
| 2,111 vB | 2,111 | 10,555 | 21,110 | 105,550 |

All fee values are satoshis. The last case costs more than a hypothetical 100,000-sat input at 50 sat/vB, even before a payment output is funded.

## Economic spendability and dust

A UTXO may remain valid but be uneconomical to spend at a given rate. The marginal cost of including an input depends on its authorization data and whether its inclusion changes the count prefixes or other transaction fields. Compare that cost to the value recovered; for a standalone payment, include output and transaction overhead as well. Dust policy is a distinct relay rule, not a universal consensus threshold or a prediction of future spendability. Existing policy estimates are not automatically appropriate for hypothetical PQ outputs.

## Fee estimation versus fee calculation

The formulas above calculate a fee given a size and target rate. Predicting the rate needed for timely confirmation requires a model of network demand, miner selection, mempool policy and confirmation targets. A PQ migration could alter these conditions. A fixed-rate comparison holds demand constant and should never be read as a prediction that actual fees will grow by the same ratio.
