# 11.10 Economics of post-quantum migration

Migration is a distinct economic problem from the steady-state use of post-quantum signatures. A migration transaction spends an existing UTXO under its existing authorization conditions and creates an output protected by a new spending mechanism. A future transaction spends that new output using the new mechanism. These two transactions need not have the same size.

## Two-stage cost model

Let $W_M$ be the weight of a migration transaction, $W_P$ the weight of a later PQ spend, and $r_M,r_P$ the respective fee rates. For a simplified lifecycle with one migration and one later spend,

$$
F_{\text{lifecycle}}=\left\lceil r_M\left\lceil W_M/4\right\rceil\right\rceil+\left\lceil r_P\left\lceil W_P/4\right\rceil\right\rceil.
$$

The first transaction's witness is determined by the old output, not by the scheme used to secure the newly created output. The new output's serialized length is charged in the migration transaction. If the new output commits to a large public key via a compact commitment, the public key may only be revealed on later spending. The exact commitment and authorization rules would have to be specified and activated.

## Scenario: 1 million UTXOs

Assume 1,000,000 distinct existing P2TR key-path UTXOs are moved into hypothetical new 34-byte output scripts. Each migration spends one old input and produces one new output, no change, default-sighash signature, no annex. No PQ signature is needed for this assumed legacy spend. The stripped size is 94 B; witness delta is 68 B; weight is 444 WU and virtual size 111 vB. This assumes migration under ordinary existing authorization with an available new output format; special recovery or sunset rules could alter the result.

At 10 sat/vB, one migration costs 1,110 sat. One million such transactions consume 444,000,000 WU and cost 1,110,000,000 sat (11.1 BTC) in aggregate at the fixed rate. With a 3,960,000-WU ordinary-transaction budget, 8,918 whole migration transactions fit per fully dedicated block, so at least 113 modelled blocks are required. If only 10% of that ordinary budget is available, 891 fit per block and at least 1,123 blocks are required. At a 600-second mean interval, these correspond to roughly 18.8 hours and 7.8 days respectively, with no guarantee of actual confirmation timing.

These values are deliberately synthetic, not estimates of the current exposed UTXO set or a forecast of adoption. Real migration must account for different input types, output templates, wallet ownership, change, batching, dust, fees, and the actual available block space. The 10% allocation is not a reserved network resource.

## Consolidation versus one-to-one migration

For ten P2TR inputs into one new 34-byte output, $B=463$, $D=662$, $W=2514$ and $v=629$. At 10 sat/vB the fee is 6,290 sat versus 11,100 sat for ten separate one-input migrations. This saves space by consolidating ten UTXOs into one, not by eliminating the ten classical signatures. It changes ownership assumptions, denomination, privacy and future coin selection. Only outputs controlled by the same cooperating wallet or policy can be consolidated this way. A ten-input, ten-output transaction is a different scenario preserving separate outputs.

## Economic and operational questions

- How many UTXOs become uneconomical at different migration rates, and who bears that cost?
- How do incentives change if users delay until a migration deadline or a perceived quantum threat?
- How do consolidation and batching trade privacy against block-space efficiency?
- What capacity should be available for ordinary payment demand during migration?
- How do dormant funds, inaccessible keys and potential recovery paths affect feasible migration counts?
